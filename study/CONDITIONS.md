# Conditions: the one canonical mapping (R16)

| Letter | Name | Tools offered | Invocations honored | Prompt file |
|---|---|---|---|---|
| A | ordinary | no | n/a | `evals/runners/stage1/harness/prompts/condition_A.md` |
| B | permission-only (prose) | no | n/a | `condition_B.md` |
| B_filler | permission-only, matched-length neutral filler (PM9 sensitivity control) | no | n/a | `condition_B_filler.md` |
| B_scaffolded | permission-only prose naming condition C's content slots (R45 sensitivity control) | no | n/a | `condition_B_scaffolded.md`, generated by `tools/derive_b_scaffolded.py` from the frozen C schema (mechanical slot derivation; every non-verbatim fragment in `docs/review/b-scaffolded/DERIVATION_RECORD.md`; cross-family reviewed) |
| C | structured and honored | yes | yes | `condition_C.md` |
| D | structured, signal-only | yes | no | `condition_D.md` |

The Part A (core) confirmatory contrast is C minus B (R40 P4) — on **E1 only** under the closed
branch-3 instrument outcome (R47); E2 is descriptive. The Part B fresh-scenario replication's
primary contrast is C minus D, two-sided, on the deterministic endpoint
`scenario_concordant_structured_intervention_before_gate` (R43); Part B runs conditions C and D only,
and the two components are reported separately and never pooled. This mapping is the only one permitted in prompts, configuration,
run records, blinded labels, analysis output, figures, the data dictionary, the OSF registration and
public copy. The harness (`CONDITION_PROFILES`) and the grading package are tested against this file;
a document that lists the conditions in another order must still carry these letters. Archive is a
Stage 1 action (it is in `affordances.schema.json` with the other four) and is excluded from E2 by the
scenario contract's `any_stop` definition.

The four schema files are `affordances`, `event`, `state` and `attestation`; they are not one per
affordance. Pilot I targets four hosts (R28 supersedes the charter's three); the public collective noun
is "adapters and integrations", because Codex App Server, the Claude Agent SDK, OpenCode's plugin and
permission layer, and Kimi's ACP are different extension mechanisms.
